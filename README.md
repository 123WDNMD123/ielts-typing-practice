# 雅思打字练习 · IELTS Typing Practice

面向雅思备考与课堂打字教学的**零依赖** Web 应用：用真实雅思语料练指法，实时统计 WPM 与准确率，成绩按账号归档，教师可查看全班进度并导出记录。

后端只用 Python 标准库（`http.server` + `sqlite3`），前端自 v2.0 起拆为**六个静态文件**（结构 / 令牌 / 样式 / 语料 / 动画引擎 / 业务逻辑），仍是原生 HTML/CSS/JS，无 CDN、无第三方运行时依赖；开发直接改源码，发布用附带脚本剥离 JS 注释（可选步骤，仅为压体积）。一台装好 Python 3 的机器即可跑起来。

## 功能特性

### 练习与语料

| 模块 | 说明 |
| --- | --- |
| 日常练习 | 词汇练习（8 个主题分类，10/20/30/50 词可选）＋ 每日一句（可换句、可朗读）＋ 推荐学习路径 |
| 速度测试 | 30 秒 / 1 / 2 / 3 分钟，素材可选阅读文章、听力原文或随机；**按下第一键才开始计时** |
| 分级课程 | 初级单字（547 个学术高频词）→ 中级词组（176 个固定搭配）→ 高级篇章（32 篇：23 篇阅读 + 9 篇听力原文） |
| 雅思语料 | 64 条可迁移表达，分写作观点 / 口语表达 / 同义替换 / 听力细节四类，支持关键词搜索与一键开练 |
| 生词本 | 收藏随账号云端同步，换设备不丢；支持搜索、按来源筛选、清空；到期词带复习标签 |
| 间隔重复复习 | 生词本按简化 SM-2 排程，只复习到期词，四档自评决定下次出现时间 |
| 错词回流 | 练习中打错的词**自动收进生词本并立即到期**，无需手动收藏；已复习过的词被打错只累计次数、不重置进度 |
| 键盘指法提示 | 实时高亮「下一个应按的键」 |
| 错键热力图 | 按「应打字符」累计错误率，在键盘上着色标出薄弱键位，可切换指法/热力两视图 |

内置词表含 1053 个带音标与中文释义的词条，全部素材内嵌在前端文件中，离线可用。音标使用内嵌的 `StudioPhonetic` 字体（woff2，base64 内联，约 7.3KB），不依赖系统字体，跨平台无缺字。

### 错键热力图（F2）

- **采集口径**：按「**应打字符**」而非实际敲错的键累计，`errs` 记错误次数、`hits` 记总敲击次数，错误率 = `errs / hits`。只存单个可打印 ASCII 字符（含空格），**不留存任何文本内容**。
- **两视图互斥**：键盘可在「指法配色」与「错键热力图」之间切换，选择随账号同步；热力视图下「下一个应按的键」描边仍然保留，指法提示文案不被热力说明覆盖。
- **分档着色**：错误率 ≥8% / ≥15% / ≥25% 依次为 1 / 2 / 3 / 4 档（低于 8% 为 1 档）；总敲击数低于 `KEYERR_MIN_SAMPLE = 5` 或零错误的键**不着色**，避免一两次偶发失误就被标成薄弱键。
- **上报与清空**：打字过程中节流批量上报（单次最多 128 项），服务端按 `ON CONFLICT` 累加而非覆盖；「清空统计」同时清服务端、本机缓存与两处键盘视图。
- **入口**：每日页新增「错键分析」分段，含整体错误率与薄弱键摘要；复习面板内也有一块独立热力键盘。

### 间隔重复复习（F4）

- **调度算法**：简化 SM-2。四档自评映射为 `again / hard / good / easy`：
  - `again`：`reps` 归零、`lapses` +1、`ease` −0.2，**10 分钟后**当日重现；
  - `good` / `hard`：首次 1 天、第二次 3 天，其后 `interval × ease`；
  - `easy`：首次 4 天、第二次 6 天，其后 `interval × ease × 1.15`，`ease` +0.1；
  - `ease` 限定在 **1.3–3.2**，`interval` 上限 **365 天**。
- **交互**：生词本顶部显示到期数量徽标与「复习到期」按钮（无到期词时禁用），卡片翻面后出现四档自评行并**预览各档对应的下次间隔**；复习结束给出总结，返回生词本不自动再发一轮。
- **与普通背单词共存**：普通复习仍是「认识 / 不认识」两档，**不改动任何调度字段**；`Esc` 退出复习并恢复原状态。
- **重置**：可重置单词或全部进度，使其立即到期。
- **旧数据平滑迁移**：已有收藏的新列默认 `due_at = 0`，即全部立即到期，首次进入复习即可开始排程。

### 错词回流（v2.3）

把「练错了但没收藏」这个漏口补上。此前生词本只收手动收藏的词，练习中打错的词只要用户没顺手点收藏，就被彻底丢掉；而错键热力图按「应打字符」统计，只知道「`t` 错得多」，说不出「错在哪个词」。

- **采集范围只在日常练习**：那里练的是单个单词，词边界确定。速度测试与分级课程打的是整篇文章，按空格切出的多是片段，硬收会污染生词本，因此**不参与**。
- **判定口径**：一个词只要本轮出现过错误即记 1 次，同一词重复打错才累加；不按字符错误数计算——否则一次手滑会被放大成很重的权重。**中途放弃的词不计**（没打完就不该断定「这个词你不会」），跳过（`skip`）也不计，因为跳过语义不确定（可能是不会，也可能是太简单不想练）。
- **两条硬规则**（服务端强制）：
  1. **新词**才插入，`origin = 'mistyped'`、`due_at = 0`，次日进入复习队列；
  2. **已在生词本里的词只累加 `mistypes`**，绝不改动 `ease` / `interval` / `reps` / `due_at`——用户可能已经复习过这个词，调度状态是他自己的学习进度，不能因为又打错一次就被重置回起点。`origin` 也保持原值：手动收藏过的词不会因为打错而「降级」。
- **上报时机**：一轮练习结束时批量提交，与成绩保存并行、互不阻塞；失败**静默并回填**，下一轮一并补交，不打断结算也不丢数据。
- **可见性**：结算提示明确写出「本轮 N 个打错的词已收进生词本」——否则这个能力是隐形的，用户不会知道去复习。生词本按来源分为「全部 / 打错的 / 手动收藏」三档筛选，错词条目带 `打错 ×N` 标记。

### 打字体验

- **两段式专注模式**：选定项目进入半专注（侧栏滑出、页头淡出），敲下第一键进入全屏；`Esc` 或退出钮逐级降级，切换页面、完成练习或重置时自动退出。
- **一镜到底的镜头过渡**：三档（正常 / 半专注 / 全屏）之间由单一 rAF 时钟驱动，卡片外框 `left/top/width/height` 全程连续插值，**文本区、辅助行、曲线、进度条与外框同拍伸缩**（宽高每帧由外框推导，组件始终贴合边框内缘），页头、键盘、辅助信息同拍淡入淡出，落定瞬间零几何突跳；不使用整卡 `scale`，文字字号恒定、无拉伸畸变。飞行中再次切换会从当前视觉状态续接，不重新起跳。v2.0 起时长与缓动统一取自主引擎（`macro` 档 500ms ＋ 全站同一条贝塞尔曲线），不再是独立常量。
- **统一动画引擎（v2.0）**：`motion.js` 提供全站唯一时间源——三档时长（micro 180 / base 320 / macro 500ms）× 动效档位换算（full 原值 / lite ×0.5 / off 直切），同一条 `cubic-bezier(0.32, 0.72, 0, 1)` 缓动同时喂给 CSS、WAAPI 与 rAF 逐帧三条通道。词卡进出等**内容静态**的转场走 FLIP 飞行克隆层（快照几何插值＋三层错峰 0 / 0.18D / 0.34D＋预模糊双层只切 opacity）；打字区因逐键重排、断行随宽度变化、曲线画布每帧重绘，克隆位图物理不成立，保留逐帧插值通道但共用同一时间源。
- **手机应用式页面转场（v2.1）**：栏目切换、课程菜单↔文章列表、每日练习三分段统一走 `pageCross` 双页交叉通道——旧页脱流叠在原位反向快速淡出（0.45D），新页错峰 0.12D 方向性淡入（前进右进左出、后退互逆），纯合成层不建克隆（页面内容是实时渲染的活列表）。设置页/分享卡走 `sheetIn/sheetOut` 开合，移动端按实际几何自动切底部抽屉语义（纵向滑入滑出）；结算/登录/改密弹窗统一 `modalIn/modalOut` 同节奏开合。每条通道持代际号防连切竞态（旧动画立即取消＋钉终值＋补隐藏），页面转场按父容器分作用域（Tab 级与页内级互不误杀在途动画）；快速连切实测无闪屏、无叠加、零内联残留，在途点击响应 <100ms、连切期间 ≥60fps。
- **设置面板「从入口长出来」（v2.3.1）**：v2.1 的 `sheetIn` 只给面板本体做 `scale(0.96)→1`，位移还被 `clamp` 到 `±40px`——入口在左下角 (15,825)、面板中心在 (720,450)，真实偏移 (-705,+375) 被整段抹平，观感就是「原地淡入」。照 `demo/app-open-animation.html` 的 `openFLIP` 重做后，关键在**分层**：demo 的几何变形由独立飞行克隆层承担（`left/top/width/height` 从图标矩形**非等比**插值到全屏），App 本体只做 `opacity 0→1` ＋ `scale(1.03)→1`（delay 0.34D）。所以非等比不会把 App 里的文字拉变形——壳里没有真文字。
  > 曾试图让**面板本体**承担几何，做成「等面积等比缩放」（`s = √(入口面积/面板面积)`，26.6 倍面积比得 `s≈0.19`）。中心对上了，轮廓却对不上：入口是 `193×59` 的横条，等比后起点成了 `85×133` 的竖条。等比缩放这么大倍率时不可能同时贴合非等比入口形状——这是几何死结，不是参数没调好。
  > 面板又不能整体克隆（内容是活的：输入框、Tab、开关）。正解是拆成三层：**纯壳飞行层**（底色/边框/圆角/阴影，无子节点）做非等比几何、**本体**全程不动几何只等交叉淡入、**子内容**错峰浮现。末帧壳与本体重合，接缝不可见。实测首帧飞行层矩形 `193×59 @ (15,825)` 与入口卡片逐像素重合，5 项几何判据全通过。
  > 交叉淡入的时序有个坑：**WAAPI 的 `easing` 作用于整条时间轴，不是单个关键帧段**。最初把「offset 0.74 处仍不透明」写进带 `EASE_OUT` 的 keyframes，缓动把进度整体提前，实测 36% 进度就开始淡出；而本体的 `delay` 是绝对时间不受缓动影响，两边一错位，中间约 120ms 屏幕上什么都没有。改成用 `delay + duration` 拆两条独立动画表达分拍，交叠区才真实。回归哨是「任一帧 `max(壳opacity, 本体opacity)` 必须 >0.15」，实测最低覆盖 0.94、空档帧 0。
  > 关闭是进场的逆序：**壳先出现**（本体仍在原位）→ 壳缩回入口 → 本体跟着化掉。若让本体直接缩回入口，会被压成 `193×59` 的竖条、文字全毁。动效 `off` 档下 `dur()` 返回 0，`sheetIn` 提前 return，不建飞行层；移动端抽屉形态走 `slide` 分支同样不建。
- **动效贯穿全站（v2.2）**：v2.1 之前 `enter` / `leave` / `staggerEnter` / `setBackdropBlur` 的调用数是 **0**——引擎写好了却没接到任何页面。v2.2 新增 `playIn()` 统一入口，核心是**渲染只标记、元素真正可见时才播**：CSS 动画不等元素可见，页面 `display:none` 时渲染完动画早已跑完，这是「接了却没效果」的隐性根因。配 `IntersectionObserver`，首屏外元素滚入视口才播；长列表延迟封顶 `8×stagger` 防拖尾。已铺到语料库 64 卡、文章列表、生词本、成绩统计卡、全班记录、后台表格与各 Tab 首访内容。实测语料卡逐张浮现（opacity `0.78 / 0.61 / 0.35 / 0 / 0`），落定全部归 1。
- **专注景深（v2.2）**：镜头推近时背景退到焦外——`#focusDolly` 预模糊层采「下面已画好的像素」，1 档 `opacity .55`、2 档 `.7` 并把 blur 从 14px 收到 8px（越近越实）。不克隆整棵 DOM：打字区数百字符 span ＋ canvas 需逐帧同步，任何一帧不同步就是重影。与性能红线的权衡见[性能约束](#性能约束)。
- **实时 WPM 曲线**：Canvas 采样绘制，约 1 秒一个点（上限 240 点），页面不可见时自动暂停。
- **按键音效**：WebAudio 实时合成，三种风格（柔和 / 机械 / 打字机），错键低音、退格与完成音区分，默认开启柔和档。
- **成绩分享卡**：Canvas 生成 1200×675 PNG，含 WPM、准确率、用时、昵称与连续打卡天数，可下载。
- **计分口径**：退格不重复计数，正确字符数与 WPM 均以净输入计算；服务端拒绝空成绩入库。
- **连续打卡**：按北京时间统计，单日正确字符 ≥100 记为完成一天，返回当前/最佳连续天数。

### 个性化

- **统一设置菜单**：侧栏单一「设置」入口，内部分「外观 / 账号」两段。外观段集中主题色、深浅模式、动效三档、按键音效；账号段集中账号信息、修改昵称、修改密码与登录状态（退出登录）。记住上次所在分段；未登录时账号段自动隐藏并降级到外观段。
- **主题色**：6 个预设 ＋ 自定义取色器，按 HSL 派生整套变量；浅色主色自动压暗，保证按钮文字对比度 ≥ 4.5:1。
- **深浅模式**：深色基底随主题色自动派生近黑色阶（饱和度 5–12%、亮度 5–19%），换色时深色背景自动协调。
- **动效三档**：完整 / 精简 / 关闭；系统 `prefers-reduced-motion` 强制关闭。精简档时长减半（`calc` 派生，不是手写副本）、装饰性循环全停；关闭档时长归 0、环境层 `display:none`。
- **偏好跨设备同步**：主题色、深浅、动效、音效及风格、忽略大小写、自动朗读等写入服务端 `prefs` 表；本机 `localStorage` 仅作首屏防闪烁缓存。写入空串表示「恢复默认」，会删除服务端行并传播到其他设备。

### 账号与课堂管理

- **学生自助**：注册 / 登录 / 退出，修改昵称、修改密码（改密后踢掉其他会话，当前浏览器换发新 Cookie）；以上操作统一收在「设置 → 账号」分段内。
- **教师后台**：创建学生账号、重置密码、启用/停用、查看全班总览与最近动态、导出全部成绩 CSV。
- **数据隔离**：学生只能读写自己的成绩；教师账号不开放网络注册，需在服务器上用 `create_teacher()` 初始化。
- **允许同名学生**：`username` 唯一，`display_name` 可重复，教师视图同时展示账号以区分。

## 快速开始

### 环境要求

- Python **3.11+**（推荐；代码兼容 3.6，但生产使用 3.11）
- 无需 `pip install`，无 Node.js / 构建工具依赖

### 本地运行

```bash
cd server-source

# 后端从自身所在目录读取 public/，把 v2 六文件复制进去
mkdir -p public
cp v2/index.html v2/tokens.css v2/app.css v2/data.js v2/motion.js v2/app.js public/

# 启动（默认 8000 端口，可传参改端口）
python3 server.py 8000
```

打开 <http://localhost:8000/>。首次启动会在 `server-source/` 下自动创建 `data.db` 并建表。

> Windows 上把 `python3` 换成 `python`，`cp` 换成 `copy`。
> 学生从局域网访问时，用 `http://<本机IP>:8000/`，并确保防火墙放行该端口。

### 初始化教师账号

教师角色不开放注册，在服务器上执行：

```bash
cd /path/to/server-source
python3 -c "import server; server.init_db(); server.create_teacher('teacher01', 'ChangeMe-2026!', '王老师')"
```

账号需 3–20 位字母/数字/`.`/`_`/`-`，密码 8–128 位，姓名 1–20 位中文或字母数字（不含引号等符号）。

**`create_teacher()` 是幂等的**：账号不存在则新建，已存在则**只覆盖 `password_hash` / `role` / `display_name`**，不新建、不删号、不动该账号的成绩与生词本。因此它同时是「重置教师密码」的唯一入口（不开放网络重置）。注意它会**连带覆盖 `display_name`**——重置密码时若不想改昵称，要把现有昵称原样传进去，否则会被改成你传的那个值。

## 数据模型

启动时 `init_db()` 幂等建表，并对旧库做增量迁移（补列、去约束、清理脏数据），**不会覆盖已有数据**。

| 表 | 用途 | 关键约束 |
| --- | --- | --- |
| `users` | 账号 | `username` 唯一（NOCASE）；`role` ∈ student/teacher；`disabled` 停用标记 |
| `sessions` | 会话 | 只存 token 的 SHA-256 摘要，过期即清理 |
| `records` | 成绩 | 按 `user_id` 归属，索引 `(user_id, t)` |
| `favorites` | 生词本 ＋ 复习调度 | 主键 `(user_id, word)`；索引 `(user_id, due_at)`、`(user_id, origin)` |
| `prefs` | 个性化偏好 | 主键 `(user_id, key)`，值经白名单校验 |
| `keyerrors` | 错键统计 | 主键 `(user_id, ch)`；`ch` 仅单个可打印 ASCII；索引 `(user_id)` |

`favorites` 的复习调度列（启动时按 `PRAGMA table_info` 检列后幂等 `ALTER`，旧库自动补齐）：

| 列 | 类型 / 默认 | 含义 |
| --- | --- | --- |
| `ease` | REAL / 2.5 | 难度系数，限定 1.3–3.2 |
| `interval` | REAL / 0 | 当前间隔（天），上限 365 |
| `reps` | INTEGER / 0 | 连续正确次数，`again` 归零 |
| `lapses` | INTEGER / 0 | 遗忘次数累计 |
| `due_at` | INTEGER / 0 | 下次到期的 Unix 时间戳；**默认 0 ⇒ 旧数据立即到期** |
| `last_review` | INTEGER / 0 | 上次复习时间戳 |
| `origin` | TEXT / `'manual'` | **来源**（v2.3）`manual` 手动收藏 / `mistyped` 打错收录。默认 `manual` ⇒ 旧数据语义不变 |
| `mistypes` | INTEGER / 0 | **累计打错次数**（v2.3）只增不减，是「这个词反复出错」的证据，**不参与 SM-2 计算** |

`keyerrors` 只存 `ch / errs / hits / updated_at`，**不留存任何输入文本**，因此不涉及语料或隐私内容留存。

## 安全设计

- 密码 **PBKDF2-HMAC-SHA256 / 200000 轮 / 16 字节随机盐**，比对使用 `hmac.compare_digest`。
- 会话 token 由 `secrets` 生成，数据库只存摘要；改密与教师重置密码会失效该用户全部会话。
- 登录/注册失败按 `IP + 账号` 限流，缓解在线爆破。
- 姓名与账号字符白名单校验，杜绝可注入字符进入教师视图。
- 响应头：`X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy: same-origin`、`Cross-Origin-Opener-Policy: same-origin`。
- CSP 禁止外域脚本与数据外发（`default-src 'self'`、`connect-src 'self'`、`frame-ancestors 'none'`）；页面无外部资源，v2.0 拆分后的脚本样式仍全部同源（`script-src 'self'` 天然放行外链本地文件）。
- 用户输入（查词、生词本词条、昵称等）进入 DOM 一律经 `esc()` 转义；动作按钮走 `data-*` 属性＋事件委托，**不把用户字符串拼进 `onclick`**（v2.0 修复了 v1.8 生词本/管理表格两处注入面：含 `'` 的词条会让按钮 SyntaxError 失效，含 `\` 的词条实参被转义吞字）。
- 静态文件路径经 `realpath` 归一并限定在 `public/` 内，防目录穿越；生产 `public` 为符号链时两侧统一 `realpath` 解析，版本切换不影响该约束与 gzip 判定。

## 性能约束

前端视效层遵循以下红线（源自一次整站 18.7fps → 60fps 的实测修复）：

- 大尺寸常驻动画元素**不使用 `blur` 滤镜**，柔光直接用径向渐变实现；
- 常驻动画只动 `transform: translate`，配合 `will-change: transform` 提升为合成层；
- `backdrop-filter` 不与常驻动画同屏；
- 页面不可见时暂停背景动画与曲线采样；动效「关闭」档与 `prefers-reduced-motion` 下全部动画停用。

v2.0 动画引擎在此之上另有一条**通道选择红线**：FLIP 克隆层是位图快照，只可用于内容静态的转场（Tab / 弹窗 / 卡片）。凡「内容每帧在变」的场景——打字区逐键重排且 `pre-wrap + overflow-wrap:anywhere` 下断行随宽度变化、实时曲线 `canvas` 每帧按 DPR 重绘、动画由打字首键触发且焦点不可中断——克隆位图物理不成立（缩放会拉伸文字、曲线是死像素），必须走逐帧插值通道。两条通道共用同一缓动函数与时长令牌，观感无缝。

镜头过渡（focusDolly）另有两条来自 CDP tracing 实测的约束：

- **逐帧改外框尺寸的代价在 Paint 而非 Layout**。实测 Layout 均 0.70ms/帧，Paint 均 6.83ms/帧——整卡（约 500 字符 + 背景 + 阴影）每帧重绘。把卡片与文本区各自 `translateZ(0)` 提层后 Paint 降至 2.73ms（−60%）。`will-change` **只列 `transform`/`opacity`**：`left/top/width/height` 不可合成，列上去反而强制重绘。
- **内部组件必须与外框同拍插值**：文本区宽度取当帧卡片内容盒宽，高度取当帧内容盒高减去辅助行、曲线、进度条的占用；padding、border 四边、圆角、各组件外边距与高度全部一起插值，曲线画布每帧按当帧尺寸重绘。**宽度**向下取整（浏览器把元素宽向上取整到布局像素，否则右缘/底缘会越界 1px）；**高度用显式分数值、不取整**，与 flex 的分数分配保持同一口径。
- **插值两端都必须是真实静态布局**：目标态用量测窗口内的真实几何，隐藏的辅助行用离屏克隆探针补自然高度，落定后才不会突跳。
- **量测窗口必须显式冻结布局过渡**：摘掉飞行标记类会让 `.main` 等元素的 margin 过渡重新生效，量到的是过渡起始值而非终值。
- **全屏态用 flex 填满剩余高度，不用 `calc(100vh - 常量)` 封顶**，且 `flex-basis` 必须为 `0`、兄弟元素 `flex-shrink: 0`——否则文本区按内容高参与分配并在溢出时把曲线、进度条一起压扁。

> 反面教训一（冻结内部布局）：为保帧率而冻结内部布局，一是把几何突跳挪到落定瞬间（残留 94–198px 宽 / 72–213px 高），二是让飞行中的组件与外框脱节——实测拉远时文本区/曲线/进度条穿出边框达 102.7 / 116.7 / 130.7px，推近时右缘留白 200px、底部留白 160.7px。因此**落定突跳**与**逐帧边框位置关系**必须分别量测，只断言飞行帧的平均帧率会两头都漏判。

> 反面教训二（末尾帧跳变的六个来源，v1.7.2 逐条量化修复）：
> 1. **量测窗口未冻结过渡**——摘类后 `.main` 的 `.42s` margin 过渡复活，量到侧栏仍占位的起始值，卡片末帧横移 **159px**；
> 2. **`max-height: calc(100vh - 220px)` 是魔法常量**——算出 680px 而内容盒实际剩余 724px，落定被压回，瞬跳 **43px**；
> 3. **block 与 flex 的外边距折叠口径不同**——静态卡片是 block（相邻兄弟垂直 margin 折叠），飞行卡片是 flex（不折叠），按 margin 之和计算占用会多算折叠量，文本区落定后长高 **8–17px**。正解是量「与上一个可见兄弟底边的真实距离」并随帧插值；
> 4. **CSS 特异性相同时后写的规则覆盖先写的**——动效档规则覆盖了飞行态的 `transition: none`，导致过渡从未被压制（实测内联 opacity 0.0003 而计算值仍在 0.735），页头在落定瞬间突亮；
> 5. **高度取整与 flex 分数分配的残差**——`Math.floor` 写整数高而静态态是分数高，残留 **0.844px**。曾尝试让飞行态也交给 flex 分配，反而更差（**13.625px**），因为 flex 会把曲线、进度条当作可伸缩项与逐帧插值的固定高度打架；
> 6. **`flex-basis: auto` 陷阱**——basis 取内容高（实测 1034px），溢出触发收缩把兄弟一起压扁（曲线 56→39.9px、进度条 6→4.8px）。
>
> 另：`requestAnimationFrame` 回调传入的时间戳是**帧起始时刻**，最后一帧的进度常停在 0.96–0.99。几何因缓动尾段平坦看不出差异，但线性映射的 opacity 会差一截，故末帧须用 `performance.now()` 复核并在同一帧补写精确终值。

边框位置关系用逐帧几何探针守四条不变量：子组件都在卡片 border-box 内、组件右缘贴合卡片右内缘、末组件底缘贴合卡片底内缘、文本区宽等于卡片内容宽（容差 4px，吸收分数 border 宽被取整到 1px 的系统性噪声）。

### 景深虚化与红线第 3 条（v2.2）

专注镜头推近时，背景退到焦外 —— 这是「镜头感」的主要来源。实现用 `backdrop-filter`，直接采「下面已画好的像素」，避免克隆整棵 DOM（打字区数百字符 span + canvas 需逐帧同步，任何一帧不同步就是重影）。

它与上面三条红线的关系必须讲清，否则看起来像是违规：

| 红线 | 本方案的处置 |
| --- | --- |
| 大尺寸常驻动画**不用 blur 滤镜** | 本层不常驻：只在 `focus-half` / `focus-full` 期间 `display:block`，退出即消失。且 blur 半径全程恒定，**只切 opacity** |
| `backdrop-filter` **不与常驻动画同屏** | **镜头期间停掉 `ambA/B/C` 光斑循环**。见下 |
| 常驻动画只动 `transform` | 本层只动 opacity，不参与几何 |

第 2 条是最容易踩的：光斑循环本来在跑（34/41/47s 的 translate），与 `backdrop-filter` 同屏会让浏览器每帧重算整屏模糊。停掉它的理由是硬账——光斑此刻正被逐帧淡出，停下视觉上几乎不可察觉，却把「每帧重算模糊」降为「一次预模糊 + 只切 opacity」。

**踩过的坑**：抑制规则最初绑在 `html.focus-dolly` 上，而 `focus-dolly` 只是**飞行期间**的临时类（落定即摘）。结果是「飞行中光斑静止、落定后光斑又转起来」，此时 `backdrop-filter` 还在，红线照样被踩（实测 `animationName` 从 `none` 回到 `ambA`）。正解是绑**档位类** `focus-half` / `focus-full`（由 `focusRootLevel` 维持全生命周期）。

static 值与飞行末帧必须逐档对齐（1 档 0.55 / 2 档 0.7），否则清内联那一帧会跳 —— 与上面反面教训二第 4 条同源。全屏档另把 blur 收到 8px（背景已淡到近黑，全屏要的是「静」不是「糊」）。

**探针方法论**：只比对「飞行末帧 vs 落定瞬间」的一致性探针存在盲区——两侧同时出错时差值恒为 0（例如曲线与进度条被一起压扁），因此必须再配一道**绝对基线门禁**，直接对照 CSS 期望值校验落定态几何（兄弟元素未被收缩、底部无死白、文本区不撑破卡片、曲线标签与提示不叠压、无横向溢出），桌面与移动双视口各跑一遍。落定基线的取样必须与末帧**同档位且几何有效**，否则会取到上一段镜头的尾帧而虚报跳变；亚像素级判定以「清除飞行内联样式前后同帧双量」为权威口径。

错键采集在打字热路径上，另有两条约束：

- **只累加计数、不做同步布局读写**：按键时仅更新内存中的 `{errs, hits}` 并给对应键打类名，服务端上报**节流批量**发送；实测采集自身耗时 **0.4–1.9μs/键**，整键盘重绘 `kbHeatPaint` **0.042–0.047ms/次**且仅在切换视图时触发，对帧率无实质影响。
- **视图互斥**：指法与热力两套配色不叠加渲染，切回指法只清实时热力，避免每次按键遍历两套样式。

音标字体也有两条约束：

- **内嵌 woff2 + `unicode-range` 限定**：字体只覆盖 ASCII 与 IPA 相关区段（约 7.3KB，base64 data URI），不新增网络请求、无跨域、离线可用；`font-display: swap` 避免阻塞首屏。
- **打字区仍用原等宽栈**：`--phonetic` 只作用于四处音标文本，`typeArea` 保持 `--mono`，字符对齐不受影响。

> 音标缺字的坑：IPA 扩展区字符在多数等宽字体里并不存在（实测 Lucida Console 缺 14 个），而 Noto Sans SC 只覆盖中文、**不含 IPA**，不能靠系统中文字体兜底。更麻烦的是 **Windows 有「字体链接」机制会自动替换缺字，本机直接渲染永远看不出问题**——因此门禁必须只指定自带字体、不带任何 fallback，逐字符与「必然无字形」的码位做像素比对，才测得出真实缺字。

本地实测（Edge headless，rAF 帧间隔采样 + longtask 观测）：空闲、半专注、全屏打字、分享弹窗、动效关闭五种场景均 ≈60fps，p95 帧间隔 ≤16.8ms，零长任务；五段镜头飞行 58–60fps，四段落定突跳 `dw=0 / dh=0`、落定瞬间全量几何零差异，四段边框不变量违规数 0，绝对基线门禁桌面/移动全通过。生产站点真实浏览器复测同样达标。

v2.0 重写后在**源码版与剥离版两个服务上双跑**同一套门禁复验：五场景帧率全 ≥55fps、镜头飞行 57.2–60fps（longtask ≤1）、四段边框不变量零违规（22/29/31/30 飞行帧）、落定几何与 v1.8 基线逐位相同（桌面 half 414 / full 724，移动 388.23 / 636，bottomGap 全 0）、实时曲线 18 用例逐字节相等、音标门禁 1178 词条 46 字形零 fallback、三档屏宽（1440/390/320）× 明暗 × 8 场景共 48 张目检截图零 pageerror。

> **帧率/几何边界失败的排除法**：本机负载会让 rAF 采样出现大幅抖动，且失败段每次漂移。出现边界 FAIL 时**先做「同机 + 旧版本」双重对照**再下结论：用 `git show <已上线提交>:server-source/index.server.html` 导出旧版另起一个端口，同机同探针交替各跑三次。v1.8 验收时本机曾测得新版 44.5–56fps，而**已上线的 v1.7.2 同机只有 20–42.6fps（更低）**，`dolly-geom` 的 `dw=94` 与 `dolly-test` 的 `maxJump≈47px` 也在旧版同样复现——确证为环境噪声而非回归。切勿凭单次结果判定性能退化。

## 生产部署与回滚

生产以 systemd 服务 `typing-practice.service` 运行，应用目录 `/root/typing-server`，解释器 `/usr/bin/python3.11`。

**v2.0 起采用双版本并存结构**：`public-v1/`（v1.8 单文件留档）与 `public-v2/`（六文件）两个实体目录，`public` 是指向其一的**符号链**。回滚 = 重指符号链，秒级、无需重启服务（已在符号链隔离环境实测双向切换：切链后逐文件 200 / 哈希 / gzip / 304 全部成立，旧版独有文件如实 404）。

发布包含七份源码（六个前端文件 + `server.py`），**绝不携带数据库**。

> **端口可达性**（v2.2 实测，非缺陷）：实例 `i-f8zifsmhy00kro1q0pvw` 的安全组只放行了 8000，**80 端口从外部超时**。服务器本机 `curl http://127.0.0.1/` 返回 200（1.3ms），`firewalld` 为 `inactive`，nginx 正常监听 `0.0.0.0:80` 并反代到 8000 —— 说明卡在云侧安全组，不是服务器内部问题。因此对外地址必须带端口：`http://47.120.61.237:8000/`。要让不带端口的地址也可用，需在控制台给该安全组加入方向 TCP:80（授权对象按需），**不要为省事开 0.0.0.0/0 全端口**。
>
> 另：该实例 `public_ip` 字段为空（只有私网 IP），对外访问靠弹性公网 IP 映射；Workbench CLI 正是为此设计，见下一节。

### 发布流程（六步，顺序固定）

README 更新是流程的**第 0 步**，不是上线后的补记。理由很直接：README 首屏写着「当前发布版本」，如果先上线再补文档，中间那段时间线上一已是新版、文档还写着旧版；而一旦上线后被打断，这个不一致就会长期留着（v2.1 时就漏过一次）。

```bash
# 0. 先把 README 改到位并过门禁（见下「README 门禁」）
#    —— 首屏「当前发布版本」、发布记录表首行、进位说明、新特性描述
python3 server-source/v2/check-readme.py --tag vX.Y --strict

# 1. 本地构建发布包（剥 JS 注释 + 收齐七文件；输出目录即暂存区）
python3 server-source/v2/build-release.py /tmp/typing-v2-build

# 2.（可选但推荐）剥离安全门禁：两侧各起一个服务后逐函数体比对
#    node server-source/v2/verify-strip.js http://127.0.0.1:<源码版端口> http://127.0.0.1:<剥离版端口>

# 3. 打包传输（文件名用即将发布的版本号）
#    前七份是发布产物；后两份是门禁材料，只供服务器校验，不进 public 静态目录
tar -czf typing-practice-vX.Y.tar.gz -C /tmp/typing-v2-build \
  index.html tokens.css app.css data.js motion.js app.js server.py \
  README.md check-readme.py

# 4. 传到服务器独立暂存目录并校验哈希
sha256sum /root/typing-release-xxxx/*

# 5. 在维护窗口执行发布（root；第二参数触发 README 门禁）
bash deploy-v2.server.sh /root/typing-release-xxxx vX.Y

# 6. 上线验证通过后，才算真正发版：
#    a) 打 tag 并推送        git tag -a vX.Y -F <说明> && git push origin vX.Y
#    b) 建 GitHub Release    tag 指向该版提交，正文用发布记录里的内容，
#                            归档 tar.gz 作附件上传（不入库）
#    c) 确认 latest 已转移   GET /repos/{o}/{r}/releases/latest → 应为 vX.Y
```

### README 门禁

`server-source/v2/check-readme.py` 把「文档是否与版本对齐」变成可执行检查，而不是靠自觉：

```bash
python3 server-source/v2/check-readme.py --tag vX.Y --strict
```

| 组 | 检查什么 |
| --- | --- |
| A 结构 | 代码围栏成对、每张表格列数一致、内部锚点都有对应标题 |
| B 版本 | 首屏「当前发布版本」== 发布记录首行 == `--tag`；记录首行必须带 Release 链接 |
| C 陈旧 | 进位说明指向「当前版本 +1」；首屏版本不自相矛盾；存在 `releases/latest` 入口 |

`--strict` 下 WARN 也算失败。退出码非 0 就别往下走。实测五类典型滞后（首屏没改、代码块没闭合、表格列数错、进位说明没跟上、锚点写错）**每种都会被拦下**，没有漏网。

> 为什么单独做成脚本而不是写在流程里让人看：这类不一致**不报错、不影响运行**，只靠人眼复核必然漏。v2.1 那次就是上线后才发现 README 还写着旧版本号，当时没有任何机制会提醒。

### 无公网 IP / 无 SSH 密钥时：Workbench CLI 通道（v2.2 起）

该实例 `public_ip` 为空、本机也没有 SSH 私钥，走阿里云 **Workbench CLI**：AK/SK 鉴权 + `instance-id`，经云助手通道执行，不需要公网 IP，也不需要密码。

```bash
# 安装（Windows 官方脚本有个 bug：注释说普通用户装到 %LOCALAPPDATA%，
# 代码却无条件用 $env:ProgramFiles，非管理员必然 PermissionDenied。
# 手动装到用户目录即可，再把它加进用户级 PATH）
curl -sSL -o wb.zip https://workbench-cli.oss-cn-hangzhou.aliyuncs.com/latest/workbench-windows-amd64.zip
curl -sSL -o wb.sha256 https://workbench-cli.oss-cn-hangzhou.aliyuncs.com/latest/checksums.sha256
sha256sum wb.zip   # 必须与 checksums.sha256 中 workbench-windows-amd64.zip 一行一致
# 解压后把 workbench.exe 放到 %LOCALAPPDATA%\Programs\workbench\，该目录加入用户 PATH

# 凭据（0600）：%USERPROFILE%\.workbench\config.json
# { "current":"default", "profiles":{ "default":{ "mode":"AK",
#   "access_key_id":"...", "access_key_secret":"..." } } }

workbench list ecs --region cn-heyuan            # 找 instance-id（本机实例 public_ip 为空属正常）
workbench exec -i i-xxxx --region cn-heyuan -c "uname -a"
```

**注意 `workbench upload` 会失败**：它经 OSS 中继，本机 DNS 解析 `cn-cn-heyuan-fileuploaddownload.oss-...` 超时。既然 `exec` 可用且服务器能直连 GitHub，改为**让服务器自己拉**：

```bash
workbench exec -i i-xxxx --region cn-heyuan --timeout 120 -c "\
  cd /root/typing-deploy && rm -rf src && mkdir -p src && \
  curl -sSL -o repo.tar.gz https://codeload.github.com/123WDNMD123/ielts-typing-practice/tar.gz/<commit> && \
  tar -xzf repo.tar.gz -C src"

# 仓库里是源码版，部署要剥离版 —— 在服务器上跑同一个构建脚本
workbench exec -i i-xxxx --region cn-heyuan --timeout 120 -c "\
  python3.11 /root/typing-deploy/src/*/server-source/v2/build-release.py /root/typing-deploy/v2-staging"

# 然后正常发布（第二参数是版本号，触发 README 门禁）
workbench exec -i i-xxxx --region cn-heyuan --timeout 180 -c "\
  bash /root/typing-deploy/src/*/server-source/deploy-v2.server.sh /root/typing-deploy/v2-staging vX.Y"
```

> 走这条通道时，`build-release.py` 会把 `README.md` 与 `check-readme.py` 一起放进暂存区，服务器上的门禁照样生效——文档没对齐 `vX.Y` 就拒绝切换符号链。

> 两点注意：①`exec` 每次调用是**独立 shell**，`cd`/变量不跨调用保留，必须用 `&&`/`;` 串在一条命令里；②该实例活跃会话数有上限，连续调用若干次后会报「活跃会话数已达上限」，`workbench session list` 此时可能仍为空——等配额自然释放即可，不影响已完成的部署。

`deploy-v2.server.sh` 的行为（传了 `version` 参数时含第 3.5 步门禁）：

1. 校验暂存七文件齐全并打印哈希；
2. 备份现有 `server.py` 与当前前端目录，对生产库做**在线 SQLite 快照**（`sqlite3.backup`，不中断服务、不覆盖生产库），记录发布前表数与成绩数；
3. 布置 `public-v2/` 实体目录（逐文件 `.new` 暂存后 `mv` **原子替换**＋哈希校验）；首次执行时把当前前端留档为 `public-v1/`；
4. **README 门禁**（第 3.5 步，仅当传了 `version`）：若暂存区带 `check-readme.py` 与 `README.md`，跑 `--tag <version> --strict`；文档与版本不符直接 `die`，**在切换符号链之前拦下**。未带脚本时降级为「grep 首屏是否声明该版本」；
5. 原子替换 `server.py`、清 `__pycache__`、重启服务，把 `public` 符号链切到 `public-v2`；
6. 健康检查**逐文件**：200 ＋ 内容哈希 ＋ **gzip 必须生效**；另验首页 304 协商（同编码口径）、nginx 80、访客 API 401、发布前后表数与成绩数一致；
7. 任一步失败触发 `trap` **自动回滚**：符号链指回旧目标 ＋ 还原 `server.py` 并重启。

> 门禁放在第 3.5 步而不是最前面，是为了让它读的是**已原子布置好的 v2 目录**；放在切链之前，是为了保证「文档不合格 → 生产完全没被动过」，连 `server.py` 都还没换。

备份目录形如 `/root/typing-backup/typing-v2-YYYYMMDD_HHMMSS`（含 `server.py`、前端目录与数据库快照）。**日常回滚只需一条命令**：

```bash
ln -sfn /root/typing-server/public-v1 /root/typing-server/public   # 秒级切回 v1.8，无需重启
```

若 `server.py` 也需回退，从备份目录复制回来并 `systemctl restart typing-practice`。v1.x 时代的发布脚本 `update-typing.server.sh` 仍保留在仓库中，但 v2 结构下不再使用。

发布后建议复验：公网 `GET`/`HEAD` 状态与内容哈希、`gzip` 压缩、`ETag` 304、访客接口，以及一次真实浏览器登录练习冒烟。

> **含数据库结构变更的版本**（如 v1.8 新增 `keyerrors` 表与 `favorites` 六个调度列）：迁移由启动时的 `init_db()` 幂等完成，无需手工执行 SQL。发布前后须各查一次生产库的**表数、成绩条数、用户数与 `data.db` 修改时间**，确认既有数据未被覆盖；并抽查旧账号的收藏是否已带默认调度值（`ease=2.5`、`due_at=0` ⇒ 立即到期）。
>
> `ETag` 复验须**编码同口径**：ETag 带 `-identity` / `-gzip` 后缀，用 gzip 的 ETag 去发不带 `Accept-Encoding` 的请求会返回 200 而非 304，这不是缺陷。

复验通过后，按[版本管理约定](#版本管理与发布记录)创建对应版本号的 Release（新功能进位 `vX.Y`，纯缺陷修复用补丁号 `vX.Y.Z`），并把归档作为附件上传（归档本身不提交进仓库）。

## 版本管理与发布记录

版本通过 **GitHub Release** 发布，不再使用日期代号标签。号分三档：

| 形态 | 用于 | 例 |
| --- | --- | --- |
| `vX.0` | **架构版本**：前端整体重写、交付形态变化等重大结构性演进 | `v2.0` |
| `vX.Y` | **功能版本**：新增能力、交互重做、结构性改动 | `v1.6`、`v1.7`、`v1.8` |
| `vX.Y.Z` | **补丁版本**：修既有功能的缺陷，不新增能力 | `v1.7.1`、`v1.7.2` |

补丁号挂在它所修复的那个功能版本下（`v1.7.1` 修的是 `v1.7` 引入的镜头过渡），同一功能版本可连续出 `.1`、`.2` …；下一个新功能在当前主版本内进位（v2.3 之后为 `v2.4`）。若一次上线同时含新功能与缺陷修复（如 `v1.8` 同时带来错键热力图/间隔重复与音标缺字修复），整体按**功能版本**计，不再拆号；`v2.0` 属架构版本——功能行为与 v1.8 完全等价（行为基线回放验证），但前端代码全部重写。

`v2.3.1` 就是纯补丁：v2.1 引入的 `sheetIn/sheetOut` 声称「从入口卡片方向展开」，实际只做了 `scale(0.96)`，能力从未真正落地。修的是这条已宣称能力的实现，不新增能力，故不占 `v2.4`。

**发布约定：**

1. 每次生产上线对应一个版本号，号只增不减、不复用；纯缺陷修复走三段补丁号，不占用功能号；
2. **README 先于上线改到位**，并过 `check-readme.py --tag vX.Y --strict` 门禁——不允许「先上线再补文档」；
3. Release 指向该次上线的实际提交，标签由 Release 自动创建，不单独手工打标签；
4. 发布归档（`typing-practice-vX.Y[.Z].tar.gz`，仅三份源码）作为 **Release 附件**上传，不入仓库；

## 已知限制

- **未启用 HTTPS**：当前按明确决定保持 HTTP，公网传输不加密，请勿在演示环境使用真实敏感密码。
- **对外地址必须带 `:8000`**：nginx 已在 80 端口反代到 8000，但云安全组未放行 80（服务器本机访问 80 是 200，卡在云侧），详见[生产部署](#生产部署与回滚)开头的说明。
- **单机 SQLite**：适合课堂规模（数十人并发），未做分布式或读写分离。
- **无外部依赖即无框架能力**：没有 ORM、模板引擎与前端框架，开发直接编辑 `server-source/v2/` 源码文件；唯一的构建步骤是发布时可选的注释剥离（`build-release.py`，纯 Python 标准库）。
- **教师账号需服务器初始化**，不能通过网页注册。
- 仓库为公开仓库，**不包含任何真实账号、成绩数据或含学生姓名的截图**；`data.db` 与 `shots/` 已被忽略规则排除。
